## Module inventory — what the be sdk exposes, by category, with entry points and docs

### Takeaway
The core repo's `src/` holds 22 production areas (incl. the `Meta` composition root and the `Abstractions` kernel) plus 4 testing companions, with 184 capability sub-folders in total; 151 hold code and 33 are empty placeholders (mostly AI, FeatureFlags, Tenancy, Messaging, Caching providers). Excluding the testing companions: 171 sub-folders, 139 with code, 32 empty. It exposes 262 distinct registration/pipeline entry methods (206 `Add*`, 27 `Use*`, 12 `Apply*`, 11 `Map*`, 4 `Require*`, 2 `Migrate*`). Identity (≈64 more entry methods) left core on 2026-10-27 for the `wow-two-sdk-beta.identity` domain repo. The SDK's own folder tree (`src/{Area}/{Module}/`) and the published `package-registry.md` give the category model a gallery can use as-is.

### Gaps
- Release status per module (shipped vs "implemented, unreleased") is recorded only in prose in `package-registry.md`, and several rows lag the code (e.g. `Jobs.Core` "unreleased" while Wheelhouse on `10.0.80-beta` calls `AddPeriodicJob`). ## Desire paths — what products hand-wire, duplicate, copy or override

### Takeaway
Products do not bypass the boot floor (0 of 30 call `UseSerilog`, `AddCors`, `UseForwardedHeaders`, `AddJwtBearer` or `MapHealthChecks` directly). The desire paths sit one layer deeper: SQLite persistence setup (no SDK one-call bundle), connection-string/`DB_CONNECTION` resolution (17 products), key/data-folder preparation (11–16 products), hand-written periodic `BackgroundService` loops (15 classes in 10 products) although `AddPeriodicJob` exists, hand-registered repositories (22 products), product-local idempotency receipts (4 products) beside unused SDK idempotency, opaque token minting/hashing (7+ products), and a cookie-accounts block repeated verbatim in 10 products. Haven carries the most explicit "extraction candidate" copies (5 remarks), and 5 products sit on stale pre-rename pins that keep local copies of now-shipped SDK types.

### Inferences
- The strongest "pave this" signals (10+ products, same shape): SQLite persistence bundle (`AddSqlitePersistence`-like, with `DB_CONNECTION`, folder creation, migrator set, readiness), a cookie-accounts preset (the 9-call block ×10), a mediator interceptor preset (×13), owner-only data/key folder creation in `AddPersistentDataProtection`, and adoption of `AddPeriodicJob` in the 9 products still running hand loops.
- Much duplication is template-seeded: the product template still ships the hand-wired `AddSqliteDatabase`/`ResolveConnectionString` pair, so fixing the template is as important as adding the SDK API.
- Adoption lag is itself a desire path: SDK pieces built from product code (`AddPeriodicJob`, `ToProblem`, idempotency) exist while consumers keep the originals; a gallery "used in" field would make the lag visible.
- Haven is the reference for "SDK lacks a hook" paths (provider/data-source hook, cookie JWT, service tokens, AI providers, OTP store); Wheelhouse is the reference for "SDK default is wrong for us" overrides (config key, migration version, SPA reserved prefixes, health predicate).
