# I18n

*Last updated: 2026-09-10*

> Locale, messages, direction and time formatting for a subtree.

## Locale

- must expose locale reactively so descendants update after a switch.
- must use an app-declared default and a documented fixed fallback without a provider.
- must accept the initial locale explicitly for SSR; server markup and first hydration use the same value.
- may consult navigator lazily for client-only preference selection after the initial render.
- must let a subtree override locale without requiring a wrapper element.
- must update document `lang` at the app root; a local override declares its language on the affected content boundary.
- must propagate text direction explicitly through `dir` and the direction context.
- must preserve caller-authored strings; translate SDK-authored messages through the resolver.

---

## Messages

- must resolve consumer override, SDK fallback, then a documented missing-key fallback.
- must accept a dictionary or resolver callback without forcing a catalog vendor.
- must support locale-sensitive plural selection; string interpolation alone is not pluralization.
- must render resolved messages as text unless an explicit trusted rich-text boundary is declared.
- must interpolate supplied variables without evaluating templates as code.
- must expose missing-key diagnostics through an opt-in handler, never a production crash.
- must keep message lookup reactive; retained resolver identity must not freeze a prior locale.

---

## Formatting

- must use locale-aware number, currency, date, time, list and relative-time formatting.
- must cache formatters by locale, options and timezone; invalidate only affected entries on a change.
- must distinguish locale from timezone; the app supplies an explicit timezone for timestamp presentation.
- must keep date-only values date-only; a timezone conversion must not shift the selected calendar date.
- must follow [type mapping](../api/type-mapping.md) for Temporal/wire conversion.
- must test locale changes, long labels, plural forms, RTL and server/client initial-value agreement.
